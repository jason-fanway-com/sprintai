## stated-total FP (Vito 510/517): FIXED, DEPLOYED, VERIFIED

**Root cause (diagnosed from real transcripts, not the failure string):** the
`findQuotedTotal` Pattern-3 alternative `comes? to` matched **"come to" inside
"Wel*come to* Vito's Pizza"** (greeting), and the greedy `\D*` then reached the
first `$10.99` inside the disambiguation question ~40 chars away. The bot was
correct — it asked "did you mean the Greek Salad or the Greek Chicken Wrap?"
and added nothing. Not the money bug; a scorer false positive. Exactly the PO
diagnosis, and the same class as the $10.95 cream-cheese case.

**Fix:** `\bcomes? to\b` (word boundaries kill "Welcome to") + `\D{0,15}` (the
amount must sit adjacent to the total-keyword; a price inside a question/options
list is not a total). Applied byte-identical to both cart-ops twins.
Committed in `d5d4ced`; test in `61d6366`.

**Red-then-green proof (`stated-total-guard.test.ts`, 6/6):**
- RED: on the old regex, the real 510 & 517 replies FAIL (read as $ total vs empty cart).
- GREEN: after fix they are correctly not-a-total.
- Guard NOT weakened: "your total is $99.99" vs $11.98 cart still FAILS; "comes to $11.98" / "$11.98 total" matching a $10.99 cart still PASS.

**Live proof (deployed edge, run `5c18e236`, case_filter [510,517], Vito):**
both cases `proofPassed=true`, `stated-total:PASS`, 0 failures. (This run the
bot added the item and quoted a correct matching total — confirms the fix still
validates real totals; the disambiguation path is covered by the unit test.)
