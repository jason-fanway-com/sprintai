## P1 — MONEY BUG: SHIPPED. Root cause was our own guard, not menu data.

**Status:** fixed, committed (`2f7e0f4`), deployed live (chat-sms only; `phantom-add-guard.ts` in the uploaded bundle). Deterministic proof green: `guard-phantom-add.test.ts` 6/6 pass — RED confirms old regex missed "for ya", GREEN confirms the fix catches "for ya" + bare item-add, plus two NO-FALSE-POSITIVE cases (real mutating add; driver-tip/fee narration).

**Why proof is the unit test, not a live run:** the guard only trips when the LLM nondeterministically narrates an add and skips the `add_item` tool. A single live case can't force that path, so the deterministic unit test is the authoritative proof it fires on the exact failure string. A full 128-pair is a general no-regression sweep (cost event) — run separately, not guard proof.

**Evidence pulled from DB (not the failure string).** NJB run `a2964ae4` case `menu-single-504`:
- customer: "I'd like a Pumpernickel Bagel please"
- bot reply: *"...I've added a Pumpernickel Bagel **for ya**. Would you like a pound of cream cheese spread... plain ($10.95) or flavored ($11.95)..."*

**Which of the three it is:** (b) **item exists, `add_item` never fired.** Pumpernickel Bagel IS on the menu — not hallucination. The cart was never written — not a readback bug. The model narrated an add and skipped the tool.

**The `$10.95` the invariant flagged is the cream-cheese UPSELL price, not a quoted total.** The `stated-total` invariant read it as a total vs empty cart. The underlying bug it surfaced is real: the bot told the customer it added an item that never entered the cart. Not weakening the invariant.

**Why the guard didn't fire (the important part).** Guard 1d (`claimsAddedWithoutMutation`, index.ts:1861) is built for exactly this — "narrated add, cart unchanged." Its regex only accepts completions `to/in your cart` or `for you`. The bot said **"for ya."** No match → guard silent → ungrounded reply shipped. Same trap the PO named: a guard that doesn't fire is worse than none. It's brittle to phrasing.

**Fix (deterministic backstop, generalizes to every shop):** broaden Guard 1d to (a) accept colloquial completions `for ya/you/u`, and (b) catch the bare item-add claim ("I've added a Pumpernickel Bagel!") ending at a clause boundary — while excluding fee/tip/service/note narration so no false positive on "$2 driver tip added." Honest fallback on trip is unchanged (never auto-adds — Jason's rule).
