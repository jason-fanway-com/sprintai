# Guard Retirement Audit — chat-sms/index.ts

**Date:** 2026-09-11
**Scope:** Backlog item 8 ("guard retirement") from `docs/2026-09-10-orderfare-po-handoff.md` §3.
**Type:** Read-only recon + spec. No code was changed, no guard was deleted, no harness/acceptance run was triggered.

## Method

1. Enumerated every guard block in `supabase/functions/chat-sms/index.ts` (now 8,370 lines, up from the 8,092 cited in the handoff doc) via header-comment markers (`// ── Guard N ...`, `// ── E1/D1/D2/P1/P2/P3/C2 ...`), plus the standalone `guardNN-*.ts` files in the same directory.
2. For each guard, searched `supabase/functions/chat-sms/*.test.ts` and `scripts/test-suite/*.test.ts` for a test that exercises its specific behavior (by function name, by literal guard-name string match, and by behavioral keyword).
3. Cross-referenced `RUNBOOK.md` and `docs/DAILY.md` for documented origin (what live incident/bug each guard was built to catch).
4. Applied the deletion rule from §4 item 5 of the handoff doc: retire only when covered by a harness/test case **and** the underlying bug is structurally superseded elsewhere. Conservative default: KEEP or NEEDS-COVERAGE-FIRST, never SAFE-TO-RETIRE, especially for money-path/cart-integrity guards.

**Caveat on test-coverage findings:** "no dedicated test found" means no test was located by name/behavior grep in this pass — it does not rule out incidental coverage inside a large integration test this pass didn't fully read. Treat "no dedicated test found" as "unverified," not "definitely untested," and re-check narrowly before acting on any NEEDS-COVERAGE-FIRST row.

## Precedent already in the file (encouraging sign)

Two guards have **already been cleanly retired** using exactly the pattern this audit should recommend: code deleted, a short comment left in place explaining what superseded it.

- **Proof Guard P3** (line ~6443, retired 2026-08-30): a regex reply-scrubber for menu hallucination, removed after false-positiving on normal phrasing ("Your total is $8.99"). Superseded by (a) deterministic Ledger rendering, (b) Guard 1g/F1 (`claimsOffMenuItem`), (c) a rewritten `verifyHallucinationGuard` in `cart-ops.ts`.
- **D2** (line ~8187, retired 2026-09-04): the pickup/delivery re-ask stripper. Removed because its only reason to exist (stripping a question Guard 2b used to append) stopped applying once Guard 2b changed. Comment explicitly warns against reintroducing it naively ("would have silently deleted the model's OWN order-type question mid-sentence").

Neither needs action here — they're listed for reference as the house style to copy.
